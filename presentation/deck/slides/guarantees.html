Every sandbox, every run

What generated code gets — and what it never gets

Gets

  • A fresh gVisor container, non-root, read-only root
  • 64 MiB writable /work scratch
  • Its memory, CPU, PID and time lease
  • Bounded output and artifacts

Never gets

  • Network, DNS or the cloud metadata service
  • API keys, tokens or host files
  • The Docker socket or the host
  • A second run: it is destroyed and cleanup is verified
These limits are enforced by the worker, not requested by the model. Each run gets a brand-new container under gVisor with all capabilities dropped and no network. Memory, CPU, process count and wall time are capped by host cgroups. After the run the worker deletes the container and confirms it is gone before releasing the lease; if cleanup cannot be verified, further execution is blocked.
