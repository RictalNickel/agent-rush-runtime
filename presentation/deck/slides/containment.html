This probe is a program we wrote to attack our own sandbox. It ran in exactly the profile production jobs use. Every network path, every host secret and every system directory was blocked. When it tried to allocate 2 gigabytes against a 256 megabyte cap, gVisor and the host cgroup killed the whole sandbox, not just the process, and the worker still verified cleanup. One honest finding: the process limit stops processes but gVisor does not count threads, so thread growth is bounded by the memory and CPU caps instead.
