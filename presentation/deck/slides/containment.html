This probe is a program we wrote to attack our own sandbox. It ran in exactly the profile production jobs use. Every network path, every host secret and every system directory was blocked. When it tried to allocate 2 gigabytes against a 256 megabyte cap, the whole sandbox ended with exit 128, not just the allocating process, and the worker still verified cleanup. We did not capture an out-of-memory counter, so we describe this as the sandbox terminating at its cap. The probe ran directly in the production sandbox profile; asking the agents to attack their own sandbox was declined by the model’s safety filter. One honest finding: the process limit stops processes but gVisor does not count threads, so thread growth is bounded by the memory and CPU caps instead.
